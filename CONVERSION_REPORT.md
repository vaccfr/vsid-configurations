# vSID config v2 conversion report

Generated by `python3 -m vsid_v2` (vSID repository, `tools/`). Each v1 airport file is rewritten in the v2 format (same file name). The v2 choice is checked against a reference model of the v1 choice on generated cases (`tests/configcases_test.cpp`); the differences accepted on purpose are listed in `tools/vsid_v2/accepted_differences.json`.

## Differences to settle with the nav

The v2 config gives another SID than v1 on these cases. Each one comes from a v1 config anomaly or from variants of equal `prio` that v1 separates by reading order only. Fixing the v1 config, or keeping the v2 behaviour, is up to the nav.

- **LFBO** prio tie between 14L and 14R (AMOLO, FINOT, FISTO, LACOU, MEN H2/H3; GAUDE, LMB A2/A3): v1 takes the variant read last (14R); v2 tries the group of 32R first (other: 14L, 32R) since B 32R has the best prio, so 14L (84 cases)  
  cases: `depRwys="14R,14L", expect="[AH] 14R *", got="[AH] 14L *"`
- **LFBO** area variant A1 (14R, airbus) ties at prio 1 with A2 (14L), which v1 reads last (FINOT, FISTO, LACOU, MEN, MORIL, RIBOU): in v1 the airbus area never gives 14R; v2 nearest sends aircraft inside the area to 14R (16 cases)  
  cases: `mode="nearest", expect="A 14L *", got="A 14R *"`
- **LFBO** area variant B1 (32L, airbus) ties at prio 1 with B2 (32R), which v1 reads last (every point): in v1 the airbus area never gives 32L; v2 nearest sends aircraft inside the area to 32L (44 cases)  
  cases: `mode="nearest", expect="B 32R *", got="B 32L *"`
- **LFPB** prio tie PN C1 (25) / M1 (07, opposing) at prio 1, only with both directions active: v1 takes C1 (read last), v2 puts the opposing entry first (8 cases)  
  cases: `waypoint="PN", depRwys="07,25,09,27,03,21", rules={"opposing": true}, expect="C 25 *", got="M 07 *"`
- **LFPG** LGL A3/A4 (north area variants) are typed PT instead of J/PT: in v1 a jet parked north gets no north variant and departs 26R (B, prio 4); v2 nearest tries the north group first and gives A 27L (spec 6) (2 cases)  
  cases: `waypoint="LGL", engine="J", mode="nearest", expect="B 26R *", got="A 27L *"`
- **LFPO** opposing variants (B, G, H, Q, R, S) tie with the normal ones (A, E, F, W, X, Y) at equal prio: v1 takes the variant read last, so with opposing active 24 keeps W and 25 keeps X (Q and R are read before them); v2 puts the opposing entries first (1100 cases)  
  cases: `rules={"opposing": true}, expect="[AEFWXY] *", got="[BGHQRS] *"`
- **LFRH** config anomaly: OMNI > '1' > 'D' has no designator (v1 reads '1' as a number and 'D' as the variant id) and offers a SID with an empty designator; v2 requires a designator and drops it (56 cases)  
  cases: `waypoint="OMNI", expect=" *", got="-"`
